# Disposable Slate TEST signing ceremony

Preparation only. **Do not execute the key-generation or signing steps until the
maintainer separately approves the ceremony.** No test or production key has been
generated by this checkpoint. Production key custody, encryption and backups remain
postponed; this worktree is NOT approved production signing storage.

## Boundary and implementation

Use only `codex/desktop-updater`, in its existing isolated worktree. The fixed
environment is `dist/test/updater-disposable-signing/`, ignored by Git, with an
additional deny-all `.gitignore` inside it. Never force-add this directory. It
contains synthetic text files, disposable credentials after approval, and public
verification results; no installer, application profile, SQLite database or stable
manifest belongs here. `0.2.0` is the synthetic signed version, NOT a change to
Slate's current application version.

`scripts/windows/disposable-test-signing.mjs` supports only:

- `preflight`: require this branch, pinned installed CLI 2.12.2, no configured
  production updater endpoint/key, no enabled updater artifact generation, and no
  inherited signing/CI/Git/Node credential-routing overrides. Values are never logged.
- `prepare`: exclusively create synthetic x64/ARM64-labelled `.txt` files, an
  encryption probe, and TEST-only metadata. Refuse an existing destination and
  symlink/junction/redirected ancestors. This does not generate any key.
- `verify`: build Gate A1 offline from its locked source for the installed Rust host, then use it with explicitly supplied local
  public key, detached signatures, synthetic files and version. Never read the
  private key. Authenticate both positive cases, then require four specific
  rejection results for each architecture label. Reject unexpected files, linked
  inputs and hardlinked files. Refuse to overwrite previous verification output.

The tooling does not implement cryptography, sign, invoke a shell, access the
network, build Slate/installers, publish, configure updater trust or install anything. Architecture
labels here exercise the workflow, not actual PE payload architecture. Existing
stable-contract policy and Gate A1 verification are unchanged.

Production exclusion is structural: no application import, build hook, Tauri
resource/glob, public key, release-staging input or stable-manifest reference points
here. No signing environment variables are set. Only the explicit manual CLI
commands below can use this key. A future production signing ceremony must use a
new identity and independently check that its fingerprint differs from this test
identity. These safeguards cannot stop a maintainer deliberately copying a key or
force-adding ignored files; never promote disposable credentials into production.

The earlier audit found a Git repository at the Windows profile root. This location
is intentionally inside an ignored worktree for DISPOSABLE TEST use only; it does
not resolve the production-storage blocker. Do not synchronize, archive, back up,
upload or share this folder or the worktree while it contains the private key.

### Windows current-user execution manifest

The standalone verifier's own Cargo `build.rs` passes MSVC linker options
`/MANIFEST:EMBED,ID=1` and `/MANIFESTUAC:level='asInvoker' uiAccess='false'`.
This embeds `RT_MANIFEST` (type 24), resource ID 1, at link time for Windows ARM64
and x64. It prevents manifestless installer-detection elevation prompts; it does
not elevate the verifier or change Windows security settings. The options are
scoped to this binary only, not Slate, its installer, or Rust test harnesses.
No sidecar or manual executable patch is needed, and no dependencies are added.

The build regression tests inspect the actual PE resource, its execution level,
and `uiAccess`, including a build in an initially empty target directory. They also
inspect the alternate Windows architecture when its Rust target is already
installed; they never install targets. Run:

```powershell
node --test scripts/windows/build-update-signature-verifier.test.mjs
if ($LASTEXITCODE -ne 0) { throw 'Stop: embedded manifest regression failed.' }
```

### Restrict the newly created TEST directory before generating credentials

This changes only that new disposable directory's DACL. No parent ACL is changed.
Run it only in the approved normal user console. Stop on any failure.

```powershell
$ErrorActionPreference = 'Stop'
$testDirectory = (Resolve-Path -LiteralPath '.\dist\test\updater-disposable-signing').Path
if ((Get-Item -LiteralPath $testDirectory).Attributes -band [IO.FileAttributes]::ReparsePoint) {
    throw 'Stop: linked directory.'
}
$signer = [Security.Principal.WindowsIdentity]::GetCurrent().User
$acl = [Security.AccessControl.DirectorySecurity]::new()
$acl.SetAccessRuleProtection($true, $false)
$acl.SetOwner($signer)
$inherit = [Security.AccessControl.InheritanceFlags]'ContainerInherit,ObjectInherit'
$acl.AddAccessRule([Security.AccessControl.FileSystemAccessRule]::new(
    $signer, 'Modify', $inherit, 'None', 'Allow'))
$acl.AddAccessRule([Security.AccessControl.FileSystemAccessRule]::new(
    [Security.Principal.SecurityIdentifier]::new('S-1-5-18'),
    'FullControl', $inherit, 'None', 'Allow'))
Set-Acl -LiteralPath $testDirectory -AclObject $acl
Get-Acl -LiteralPath $testDirectory | Format-List Owner, AreAccessRulesProtected, Access
```

Verify only your current account and SYSTEM have allow entries and inheritance is
disabled. Existing synthetic files may retain old ACL entries, but they contain no
credentials. Keys created subsequently must inherit the restricted ACL; inspect
their ACLs after generation without reading their contents. This is not protection
against other software running as your user, administrators or SYSTEM. Do not use
this procedure for production keys.

## Discard after testing

Do not reuse this identity or back it up. First close the signing console and any
process that might retain the passphrase. Confirm no key path/value/password has
been exported into shell/user/machine environment variables; this workflow exports
none. Keep only a public fingerprint/result if needed, not the private key.

For separately approved disposal, use the following from a fresh PowerShell 7
console after closing the signing console. It checks every ancestor and child for
reparse points, rejects unexpected entries and removes files individually followed
by empty directories only. No recursive delete or Git cleanup is used. Stop on any
failure; do not broaden deletion scope.

```powershell
$ErrorActionPreference = 'Stop'
$worktree = 'C:\Users\kim16\Documents\ChatGPT\Tin\.worktrees\codex-desktop-updater'
$testDirectory = Join-Path $worktree 'dist\test\updater-disposable-signing'
$cursor = $testDirectory
while ($cursor) {
    if ((Get-Item -LiteralPath $cursor -Force).Attributes -band [IO.FileAttributes]::ReparsePoint) {
        throw 'Stop: linked path.'
    }
    $parent = [IO.Directory]::GetParent($cursor)
    $cursor = if ($null -eq $parent) { $null } else { $parent.FullName }
}
$allowed = @('.gitignore', 'TEST-ONLY.json', 'disposable-test.key', 'disposable-test.key.pub',
    'encryption-probe.txt', 'encryption-probe.txt.sig', 'synthetic-x64.txt',
    'synthetic-x64.txt.sig', 'synthetic-arm64.txt', 'synthetic-arm64.txt.sig')
$files = @()
$negativeDirectory = Join-Path $testDirectory 'negative-cases'
foreach ($item in Get-ChildItem -LiteralPath $testDirectory -Force) {
    if ($item.Attributes -band [IO.FileAttributes]::ReparsePoint) { throw 'Stop: linked child.' }
    if ($item.PSIsContainer) {
        if ($item.Name -cne 'negative-cases') { throw 'Stop: unexpected directory.' }
        foreach ($child in Get-ChildItem -LiteralPath $negativeDirectory -Force) {
            if ($child.PSIsContainer -or ($child.Attributes -band [IO.FileAttributes]::ReparsePoint) -or
                $child.Name -cnotmatch '^(incorrect-public-key\.pub|tampered-(x64|arm64)\.txt|corrupted-(x64|arm64)\.sig)$') {
                throw 'Stop: unexpected negative-case entry.'
            }
            $files += $child.FullName
        }
    } else {
        if ($allowed -cnotcontains $item.Name) { throw 'Stop: unexpected file.' }
        $files += $item.FullName
    }
}
foreach ($file in $files) { Remove-Item -LiteralPath $file -Force }
if (Test-Path -LiteralPath $negativeDirectory) { [IO.Directory]::Delete($negativeDirectory, $false) }
[IO.Directory]::Delete($testDirectory, $false)
if (Test-Path -LiteralPath $testDirectory) { throw 'Stop: disposal incomplete.' }
```

Clear the disposable passphrase from any temporary password-manager item. No
disposal is performed by this checkpoint or its scripts.

Ordinary deletion is **not guaranteed secure erasure on SSDs**, snapshots or backup
systems. Long random passphrase encryption, no synchronization/backups and prompt
disposal reduce risk but do not erase historical copies. If the identity is exposed,
discard it and never authorize it anywhere; it has no production trust to revoke.
